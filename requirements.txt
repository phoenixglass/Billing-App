# =============================================================================
# FULLY PINNED DEPENDENCIES — DO NOT LOOSEN THESE INTO RANGES
# =============================================================================
#
# Why every package is pinned to an exact version, including ones we don't
# import directly:
#
# Streamlit Cloud reinstalls dependencies from this file on every deploy and
# resolves each range to the newest version available at that moment. A range
# means a deploy can pull in code we never tested, with no commit on our side.
#
# That is exactly what took the app down: `streamlit` requires only
# "starlette<2,>=0.46.0", so a deploy picked up starlette 1.4.0 on release.
# 1.4.0 added a required keyword-only `thread_minimum_size` argument to
# GZipResponder.__init__, which Streamlit 1.61.0 does not pass. Every
# gzip-encoded request raised TypeError, the health endpoints returned 500,
# and the app never booted ("Oh no. Error running app.").
#
# Note that pinning only our direct dependencies would NOT have prevented this.
# starlette is a transitive dependency — pulled in by streamlit, never named by
# us. Only a complete lockfile, transitive packages included, makes deploys
# reproducible.
#
# The versions below are the exact set Streamlit Cloud resolved on its own
# (Python 3.14), so they are known to install and run together there. The one
# deliberate change is starlette, held at 1.3.1 — the last release compatible
# with Streamlit's gzip middleware.
#
# -----------------------------------------------------------------------------
# Upgrading
# -----------------------------------------------------------------------------
# Pinning trades automatic updates for predictability, so upgrade on purpose:
#
#   1. Run `pip-audit` regularly — pinned versions do not pick up security
#      patches on their own. This is the tradeoff, not an oversight.
#   2. Bump versions in a branch, never directly on main.
#   3. Verify the app actually serves traffic before merging. A boot check is
#      not enough: this outage did not surface until a request arrived, so
#      confirm the health endpoint responds 200:
#        streamlit run app.py --server.port 8501 &
#        curl -sS -o /dev/null -w '%{http_code}\n' \
#          -H 'Accept-Encoding: gzip' http://localhost:8501/_stcore/health
#   4. Re-check `starlette` specifically. It can be unpinned only once
#      Streamlit's MediaAwareGZipMiddleware passes `thread_minimum_size`
#      (or otherwise supports starlette >= 1.4).
#
# =============================================================================
